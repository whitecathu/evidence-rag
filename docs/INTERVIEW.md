# 面试讲解

## 60 秒介绍

我做了一个技术文档知识库，把解析、索引、问答和证据展示做成可运行闭环。输入是 Markdown、TXT 或文本 PDF，输出不仅是回答，还有可展开的原文来源。检索采用 BM25 与向量召回的 RRF 融合，支持接入重排 API。我另外维护了 60 条证据标注题，用于固定条件下的检索对比。当前已验证离线工程流程，真实模型质量还需要配置 API 后测量。

## 常见追问

**为什么用 RRF？** 两路原始分数尺度不同，RRF 按名次融合，减少直接调分数权重的依赖；代价是忽略分数之间的距离。k=60 是基线参数，应使用固定集调优，不能声称最优。

**为什么标题分块？** 标题提供定位与上下文，重叠缓解长段落边界切断。当前是确定性字符窗口，没有把它包装成语义分块。复杂 PDF 的阅读顺序与表格仍是限制。

**怎么处理幻觉？** 提供检索证据、要求引用、空库直接拒答、校验引用编号。模型仍可能引用不支持答案的片段，因此需要语义人工审核，不能说“彻底消除幻觉”。

**如何保证删除一致性？** 先删 Qdrant 点，再删 SQLite。失败不报成功，重试是幂等方向。生产场景可引入 outbox/删除墓碑与后台重试，当前没有实现跨库原子事务。

**为什么不用复杂分布式组件？** 目标是本地可演示项目，SQLite + Qdrant local 降低启动成本；Compose 提供独立 Qdrant 路径。没有大规模性能证据时不添加“百万文档”描述。

**指标怎么来的？** Recall/MRR 由证据标注集合计算，报告区分 demo/live。简历只能引用特定提交、模型与数据集的实测数字。
